# What the symbol table lists

**Level:** 201 · for anyone who has opened Ghidra's Symbol Table and its filter dialog and wondered what the checkboxes select

**One line:** Ghidra's Symbol Table lists every name in a program with the place the name came from — the file, auto-analysis, you, or nobody — and its Symbol Table Filter dialog is a query in three parts: a checked source, *and* a checked type, *and* the advanced filters, which are *or*-ed together and wave through every type they do not apply to; run through Ghidra's own filter class on a real executable, that is why *Unreferenced* lists none of the program's functions, not even the one nothing calls, and *Not In Memory* lets every function through.

## The program

One of each kind of name, and a `main` that uses most of them — [`demo/symbols.c`](demo/symbols.c):

```c
/* A program with one of each kind of name Ghidra's Symbol Table lists -- the
   file this page builds, strips, and hands to Ghidra's headless analyzer. */
#include <stdio.h>

/* Global data with a value. */
int counter = 7;

/* A string, and a pointer seven bytes into it: an address inside a data item
   rather than at its start. */
const char greeting[] = "hello, symbols";
const char *tail = greeting + 7;

/* static: a name only this file can use -- and still a name in the file. */
static int helper(int x)
{
    return x * 2;
}

int twice(int x)
{
    return helper(x);
}

/* Reached only through the table below: no call instruction names it. */
int via_table(int x)
{
    return x + counter;
}

int (*const table[])(int) = { via_table };

/* Nothing calls this, and nothing holds its address. */
int orphan(int x)
{
    printf("nobody calls this: %d\n", x);
    return x + 1;
}

int main(void)
{
    printf("twice(21) = %d\n", twice(21));
    printf("table[0](1) = %d\n", table[0](1));
    puts(tail);
    return 0;
}
```

| Name | What it is there to show |
|---|---|
| `counter` | global data with a value |
| `greeting`, `tail` | a string, and a pointer seven bytes into it — an address inside a data item rather than at its start |
| `helper` | `static`: a name no other file can use, and still a name in this one |
| `twice` | a function called the ordinary way |
| `via_table`, `table` | a function whose address sits in a table, so that no call instruction names it |
| `orphan` | a function nothing calls and nothing points to |

Build it, run it, and ask the file which names it holds — the program's own, split into global and local by the case of the letter `nm` prints beside each, and the library functions it calls — then strip it and ask again:

`helper` is the one local name: `static` made it one, and the symbol table keeps it anyway. `strip` removes every name the program defines and keeps the two it uses from a library — on Linux in the dynamic symbol table, on a Mac in the ordinary one — because the dynamic linker looks them up by name. The string and the program are still there. And no byte of the file spells `objc_msgSend_rtp`, which matters in a moment.

## The table

In the Code Browser, *Window → Symbol Table* opens it. [`demo/symbol_table.sh`](demo/symbol_table.sh) builds the program, hands it to the headless analyzer, and runs [`SymbolTableTour.java`](demo/SymbolTableTour.java), which prints the rows the window would show and then works through everything else on this page:

```bash
#!/usr/bin/env bash
# Build symbols.c, hand the program to Ghidra's headless analyzer, and print its
# Symbol Table as SymbolTableTour.java reads it: the rows, the queries the
# Symbol Table Filter dialog builds -- run through Ghidra's own filter class --
# and what renaming, deleting and pinning a symbol do.
#
#   demo/symbol_table.sh            the clang -O0 build, with its symbol table
#   demo/symbol_table.sh -s         the same build, stripped
#   demo/symbol_table.sh <binary>   an executable built elsewhere -- by GCC in Docker, say
#
# Needs a Ghidra install. Homebrew's is found through `brew --prefix ghidra`;
# any other one through GHIDRA_INSTALL_DIR, the folder holding support/.
set -eu
here=$(cd "$(dirname "$0")" && pwd)
ghidra=${GHIDRA_INSTALL_DIR:-$(brew --prefix ghidra)/libexec}
work=$(mktemp -d)
trap 'rm -rf "$work"' EXIT

if [ $# -ge 1 ] && [ -f "$1" ]; then
    binary=$1
else
    binary=$work/symbols
    cc -std=c17 -Wall -Wextra -O0 -o "$binary" "$here/symbols.c"
    if [ "${1:-}" = -s ]; then
        strip "$binary"
    fi
fi

"$ghidra/support/analyzeHeadless" "$work" symbols -import "$binary" \
    -scriptPath "$here" \
    -postScript SymbolTableTour.java "$work/tour.txt" \
    -deleteProject > "$work/ghidra.log" 2>&1 || { cat "$work/ghidra.log"; exit 1; }

# A post-script that throws does not fail analyzeHeadless; a missing file does.
[ -s "$work/tour.txt" ] || { cat "$work/ghidra.log"; exit 1; }
cat "$work/tour.txt"
```

The script does not imitate the window; it borrows from it. The rows are gathered the way [`SymbolTableModel` ↗](https://github.com/NationalSecurityAgency/ghidra/blob/Ghidra_12.1.3_build/Ghidra/Features/Base/src/main/java/ghidra/app/plugin/core/symtable/SymbolTableModel.java) gathers them, each column is computed with the code [`AbstractSymbolTableModel` ↗](https://github.com/NationalSecurityAgency/ghidra/blob/Ghidra_12.1.3_build/Ghidra/Features/Base/src/main/java/ghidra/app/plugin/core/symtable/AbstractSymbolTableModel.java) uses for it, and every filter decision on this page is made by the dialog's own [`NewSymbolFilter` ↗](https://github.com/NationalSecurityAgency/ghidra/blob/Ghidra_12.1.3_build/Ghidra/Features/Base/src/main/java/ghidra/app/plugin/core/symtable/NewSymbolFilter.java) — whose setters are package-private, because the dialog is their only caller, so the script reaches them by reflection.

Everything Ghidra printed on this page was produced on 2026-09-14 by Ghidra 12.1.3 from Homebrew on OpenJDK 25, on an x86-64 Mac running macOS 26 with Apple clang 21. CI does not run it — the runners have no Ghidra — so each block is a *Real output* fence that says so, and the program the fences describe is the one the verified block above built. Seventeen rows, for a program with nine names of its own. Read them a column at a time.

**Name and Location.** `_printf` and `_puts` are there twice: as an *External Function* at `EXTERNAL:00000001`, an address in no memory at all that stands for wherever the library puts the function, and as a *Thunk Function* in the program, the stub that jumps there. `_main` and `entry` share `100000630`: `_main` is the file's name for it, and `entry` is Ghidra's name for the address the file's entry-point load command gives. `__mh_execute_header` and `MACH_HEADER` share the file's first byte: the first is a symbol the linker writes into every Mach-O executable, and the second a label Ghidra's Mach-O loader adds, its [`MachoProgramBuilder` ↗](https://github.com/NationalSecurityAgency/ghidra/blob/Ghidra_12.1.3_build/Ghidra/Features/Base/src/main/java/ghidra/app/util/opinion/MachoProgramBuilder.java)'s `HEADER_SYMBOL`. The same loader creates `_objc_msgSend_rtp` at `fffeff00`, from a constant of Ghidra's Objective-C 1 support, [`Objc1Constants` ↗](https://github.com/NationalSecurityAgency/ghidra/blob/Ghidra_12.1.3_build/Ghidra/Features/Base/src/main/java/ghidra/app/util/bin/format/objc/objc1/Objc1Constants.java) — a name the `grep` above found nowhere in the file.

**Type.** *Function*, *Thunk Function*, *External Function*, *Data Label*, and a plain *Label* for `_objc_msgSend_rtp`, which labels an address with nothing at it. The non-label types — parameters, local variables, namespaces, classes, libraries — are rows too, once their boxes are checked.

**Namespace** is Ghidra's scope, not C's. Every name the program defines is `Global`, `_helper` included, although `static` made it local to its file; the two library functions are in `/usr/lib/libSystem.B.dylib`, the library the file says they come from. A symbol is in a namespace other than `Global` when it belongs to something — a parameter to its function, a method to its class.

**Source** is where the name came from, and every row here says `Imported`: from the file — its symbol table, its list of exports, its load commands — or from the loader that read it. The others are `Analysis`, a name auto-analysis gave something; `User Defined`, a name you gave it; `Default`, a name nobody gave it; and `AI`. [`SourceType` ↗](https://github.com/NationalSecurityAgency/ghidra/blob/Ghidra_12.1.3_build/Ghidra/Framework/SoftwareModeling/src/main/java/ghidra/program/model/symbol/SourceType.java) has those five values, and the dialog has a checkbox for each, with `Default` split into functions and labels; the help page installed with 12.1.3 describes the dialog without its `AI` box.

**Refs** and **Offcut** are the *Reference Count* and *Offcut Ref Count* columns. A reference is to an address, and the table counts it on the address's primary symbol: `entry` has two, and `_main`, at the same address, none. `_greeting` has one reference and one offcut reference — the column counts the addresses *inside* the symbol's data or instruction that something points to, and `tail` points seven bytes in. The window marks a non-primary name by its colour; the script writes `non-primary` at the end of the row.

None of these is in the program's database. A default label is *dynamic*: it exists wherever a reference lands and no stored symbol does, and its name is worked out from what is at that address whenever it is asked for. The window finds them by visiting every address a reference lands on, and does it only when the filter could accept one — which is why the box starts unchecked: on this small program they are already twenty-two rows of thirty-nine. The name comes from [`SymbolUtilities` ↗](https://github.com/NationalSecurityAgency/ghidra/blob/Ghidra_12.1.3_build/Ghidra/Framework/SoftwareModeling/src/main/java/ghidra/program/model/symbol/SymbolUtilities.java). Data whose type has a label prefix gives the prefix — `s_` and the text for a string, `PTR_` for a pointer, `nlist_` for an entry of the Mach-O symbol table — and an address inside a named item is that name and the distance, `_greeting+7`. An address with no such data is named for the strongest reference to it, as [`BigRefListV0.getRefLevel` ↗](https://github.com/NationalSecurityAgency/ghidra/blob/Ghidra_12.1.3_build/Ghidra/Framework/SoftwareModeling/src/main/java/ghidra/program/database/references/BigRefListV0.java) ranks them: `EXT_` for an external entry point, `SUB_` for a call, `DAT_` for a read or a pointer, `LAB_` for a jump, `UNK_` for anything else — and `FUN_` wherever a function starts. The `nlist_` and `s__` rows, from `100003071` on, are in `__LINKEDIT`, which starts at `100003000`: the part of the file that holds what the linkers need, symbol table entries and names spelled out as strings.

```text
show a symbol if
    its source is one of the checked sources
and its type is one of the checked types
and ( none of the checked advanced filters applies to its type
      or one of the checked advanced filters that apply accepts it )
```

Each advanced filter declares the types it applies to, and is grayed out until one of those is checked: *Register Variables* and *Stack Variables* apply only to parameters and local variables, and neither box is checked. Seven imports, the C runtime's among them, and none of the program's functions. `orphan` is an entry point there too, and it has two more references, from the unwind tables: its entry in `.eh_frame_hdr`'s sorted index and its record in `.eh_frame`. On a real executable, then, *Unreferenced* means that not even the file's own tables point at an address. To find a function nothing calls, read its references instead — the [*Symbol References* ↗](https://github.com/NationalSecurityAgency/ghidra/blob/Ghidra_12.1.3_build/Ghidra/Features/Base/src/main/help/help/topics/SymbolTablePlugin/symbol_references.htm) window lists them — and look for one whose references are all an entry point and a table.

## If you are coming from another language

**Rust.** The same table, filled by the same linker: the Rust library's [The linker ↗](https://masiarek.github.io/rust-learning-library/20_Compilers/the_linker/index.html) shows an object file's list of the symbols it defines and the symbols it needs, and the mangled names Rust puts in the first list, which is what a Rust binary brings to this table. Its [Reading a backtrace ↗](https://masiarek.github.io/rust-learning-library/17_Option_and_Result/reading_a_backtrace/index.html) is where the names in a panic's backtrace come from that table when a build has no debug information.

**Python.** Python has a symbol table too — its compiler builds one for every scope — and the standard library's `symtable` module hands it over:

<!-- output:symbol_table_names_py -->
*Verified output of [`symbol_table_names_py.py`](examples/symbol_table_names_py.py) — regenerated by `tools/run_examples.py`, never hand-typed.*

```text
== top ==
  _helper  assigned global
  twice    assigned global referenced
  orphan   assigned global
  print    global referenced
== _helper ==
  x        parameter referenced
== twice ==
  x        parameter referenced
  _helper  global referenced
== orphan ==
  x        parameter referenced
  print    global referenced
```
<!-- /output -->

At the top level `orphan` is assigned and never read — and so is `_helper`, whose only reader is inside `twice`, where it appears as a global that is referenced. *Referenced* answers a question about one scope, as *Unreferenced* in Ghidra answers one about one address, and neither is "does anything use this". The leading underscore that makes `_helper` private by convention changes nothing in the table, as `static` changed nothing in Ghidra's Namespace column.

**ABAP.** *(Not machine-checked — CI cannot run ABAP.)* The repository is the symbol table, and nothing is ever stripped from it: every program, class, method and function module is an object with a name, and the where-used list is the query — over source, as Ghidra's references are over machine code. What it cannot see is a call built from a value at run time, `CALL FUNCTION lv_name`, which is ABAP's `via_table`: reached, and named by nothing that says so.
